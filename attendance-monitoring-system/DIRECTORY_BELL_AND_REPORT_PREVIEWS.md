# Student directory, header notifications, and report previews

Students & colleges now separates Student record, Add a college and Add a course into individual cards. The directory appears first on phones, with search above compact student cards and active/archived filters. College/course details expand on demand. Server-side search matches name, personal ID, institution, college and course; numbered pagination uses ten records per page and exact counts beyond the old 1000-row API default. Edit/archive actions retain their existing authorization. Student tokens are not included in directory responses.

The header bell sits between the account badge and Sign out. Administrators see exact unread counts and a short notification panel linking to Review center. Approved students see only their own recent attendance updates and a link to attendance history; those updates are not represented as an unread inbox. The bell clears on sign-out/account changes and refreshes every 15 seconds. The panel supports outside click/Escape dismissal and fits below the button on mobile.

Every newly generated CSV, Excel, DOCX or PDF report now has a matching PDF preview from the same rows in the background worker. PDF exports reuse the original PDF; other formats store a companion `.preview.pdf`. The bucket remains private. Report status returns preview/download signed URLs with the existing ten-minute expiry; Refresh expired links renews them without regenerating the report. Historical non-PDF jobs created before this change do not have companion previews and must be regenerated.

PDF.js 6.5.438 is pinned and served locally through an explicit two-file whitelist. Preview rendering happens in the browser, with per-page numbered navigation, fit-width/100%/150%/200% zoom, and accessible extracted page text. This avoids blank native PDF frames on phones. The PDF worker and document are destroyed on navigation/sign-out. A separate signed PDF link remains available. No third-party document viewer receives the private report.

Validation: directory API-filter unit tests; rollback SQL fixtures with 125 student records, search, stable pages, archived records, private execution and token exclusion; read-only HTTP authorization checks; all four report worker formats with PDF companion validation; renderer-asset whitelist tests; mobile tests of compact cards/search, three separate forms, bell order/count/panel, generated preview display, two-page navigation, zoom and accessible text. UI fixtures contain only sample data. The report bucket was confirmed private. No real student record or attendance decision was edited during testing.
